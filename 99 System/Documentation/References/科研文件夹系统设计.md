# 科研文件夹系统设计

推荐将科研内容统一放在 `文稿/科研/`，内部只设三个主目录：知识点、论文阅读、项目。用首页和链接把它们连接起来：**知识负责理解，论文负责来源，项目负责行动和证据。**

本次完成的是设计与可导入模板包，原 Obsidian 库没有被修改。模板包包含三篇现有知识笔记的副本及其两份引用图片、论文模板、四个 Bases 文件和一个示例执行项目。不是已经安装并验收的完整运行系统。

## 1. 文件结构

```text
文稿/科研/
├── 科研首页.md
├── 01_知识点/
│   ├── 知识首页.md
│   ├── RL/RL.md
│   ├── RL_INFRA/RL infra.md
│   ├── EMBODIED/Embodied RL Codebase Mastery — 16 Week Roadmap.md
│   └── _模板/概念模板.md
├── 02_论文阅读/
│   ├── 论文首页.md
│   ├── 论文库.base
│   ├── 论文/标题 (arXiv-ID).md
│   ├── PDF/标题 (arXiv-ID).pdf
│   └── _模板/arxiv-paper.md
└── 03_项目/
    ├── 项目首页.md
    ├── 项目库.base
    ├── 任务库.base
    ├── 项目工作.base
    ├── _模板/项目模板、里程碑模板、任务模板
    └── P001-具身RL代码掌握/
        ├── P001-具身RL代码掌握.md
        ├── 里程碑/M01…M04.md
        ├── 任务/T001…T003.md
        ├── 记录/
        └── 产出/
```

论文和 PDF 目录分开，但用相同的“标题 + arXiv ID”成对命名。这与现有 Paper Importer 的实际输出一致，省去导入后再移动文件的步骤。每篇论文独立管理，不必额外创建一层同名文件夹。

旧笔记的图片继续使用 `_文稿附件/` 中的原路径；模板包附带实际被三篇笔记引用的图片，以便预览。未来新论文 PDF 全部进入论文区。

## 2. 知识区：保留三条主线，按需要拆概念

按你的要求，RL、RL infra、Embodied 三篇笔记全部放在知识区。16 周路线是学习路径，保留在 EMBODIED；实际执行状态、时间与成果放项目区，并链接回路线。

| 主线 | 主要内容 | 后续适合拆出的概念 |
| --- | --- | --- |
| RL | 理论和推导 | MDP、Bellman、策略梯度、GAE、PPO、Successor Features |
| RL_INFRA | 算法如何在工程中运行 | Tensor、VecEnv、Storage、训练循环、非对称 Actor-Critic |
| EMBODIED | 机器人与具身控制 | 观测、动作、PD、奖励、Sim-to-real、运动跟踪、VLA 接口 |

第一版保留完整原笔记，不强行切碎公式和代码。以后一个概念被多个论文或项目引用时，再创建独立概念页。概念模板包含定义、条件、机制、最小例子、易错点、来源与实际应用。

现有 `RL infra.md` 中的 Asymmetric Actor-Critic 是可复用解释；SONIC、BFM-Zero 如何用它属于各自论文页。现有 RL 中未完成的 PPO 推导保持未完成，不把缺失内容自动补成结论。

## 3. 论文区：Paper Importer + PDF++

已经核对你的实际插件目录：安装并启用了 Paper Importer 1.5.1 与 PDF++ 0.40.31。Paper Importer 尚无保存设置文件，当前会采用默认目录；设计中改为论文区的明确路径。

### 插件筛选

| 工具 | 作用与判断 | 本方案 |
| --- | --- | --- |
| [Paper Importer](https://github.com/chenzhekl/obsidian_paper_importer) | 从 arXiv ID/URL 下载原文并生成元数据笔记，支持自定义模板 | 主导入器，沿用已安装插件 |
| [PDF++](https://github.com/RyotaUshio/obsidian-pdf-plus) | 在原生 PDF 阅读器中通过选区反链高亮、区域引用与旁注建立阅读联系 | 主阅读与批注工具 |
| [Papers](https://github.com/willjhliang/obsidian-papers) | 可从 arXiv 搜索、下载并建立论文笔记 | 替代导入器，不与 Paper Importer 同时维护两份输出 |
| [Zotero Integration](https://github.com/community-archive/obsidian-zotero-integration) | 导入 Zotero 引文、笔记与 PDF 批注，需 Better BibTeX | 以后有引用管理需求时再加 |
| [Annotator](https://github.com/elias-sundqvist/obsidian-annotator) | 提供侧栏批注，保存于本地 Markdown；文档列出部分跨平台问题 | 不作为新系统核心 |
| [PDF++ Exporter](https://github.com/jldiaz/pdfplus-exporter) | 将旁注导出为标准带高亮和弹窗评论的独立 PDF | 分享批注时选装 |
| [Paper Clipper](https://github.com/ras0q/obsidian-paper-clipper) | 提供论文导入；仓库已归档 | 不选作核心组件 |

### 准确设置

在 Obsidian → 设置 → Paper Importer 中填入：

```text
PDF folder:
文稿/科研/02_论文阅读/PDF

Note folder:
文稿/科研/02_论文阅读/论文

Custom template file:
文稿/科研/02_论文阅读/_模板/arxiv-paper.md
```

对应配置也保存在同目录的 `paper-importer-settings.json`，供配置时核对；它没有被写入实际插件目录。

命令面板使用 **Paper Importer: Import metadata and PDF from arXiv**。输入 ID，例如 `1706.03762`，或标准 `https://arxiv.org/abs/1706.03762`。优先输入 ID，避免 PDF 链接后缀或查询参数影响解析。[官方用法](https://github.com/chenzhekl/obsidian_paper_importer#how-to-use)

模板直接使用已安装导入器支持的变量。`pdf_link` 会生成本地 `[[路径]]`，不再套另一层双括号。标题、摘要字段交由导入器处理 YAML 转义；作者输出放在正文，避免名字标点影响属性解析。模板本身含占位符，**要在源码模式编辑，替换后才是普通论文笔记**。[模板说明](https://github.com/chenzhekl/obsidian_paper_importer#template-customization)

### 一篇论文内怎样写笔记

每篇论文只有一篇主笔记，包含：一句话结论、为什么读、问题/方法/证据、逐页批注、公式与图表、疑问与局限、可复用知识、实验线索、阅读记录。

阅读时主笔记在左，PDF 在右。选中原文，用 PDF++ 复制选区链接和引用，粘贴进该主笔记的“逐页批注”，紧接着写理解。链接保留原文页码和选区信息，点击可定位回 PDF。原文中的高亮反链也可帮助找到对应旁注。[PDF++ 文档](https://ryotaushio.github.io/obsidian-pdf-plus/)

建议开启 `Highlight backlinks in PDF viewer`，按需开启只显示当前页反链。颜色约定为黄=结论、蓝=方法、绿=实验、红=疑问。颜色辅助扫描，评论用文字保存。

**这里“在论文内增添笔记”指在 Obsidian 阅读工作区内、围绕这一篇论文持续增添批注，并能定位回原文。默认评论保存在该论文的 Markdown 笔记中，不直接写进 PDF 二进制。** PDF++ 的直接写回 PDF 模式被作者标为实验功能，第一版不依赖它。[写回 PDF 的官方说明](https://github.com/RyotaUshio/obsidian-pdf-plus#note-on-saving-annotations-directly-in-pdf)

需要分享一份别人用普通阅读器也能看到批注的 PDF 时，可选 PDF++ Exporter。它生成副本，评论提取有启发式限制，不是任意 Markdown 的完全还原，也不是双向同步。[Exporter 说明](https://github.com/jldiaz/pdfplus-exporter)

### 生命周期与版本

论文状态为 `inbox → skimming → reading → synthesized`，搁置用 `archived`。主题与关联项目记在属性中，位置保持固定。

论文出新版本时，导入带版本号的 ID并检查实际输出：确认生成的是新 PDF 和新笔记，而不是复用旧文件；两份笔记互相链接。不要覆盖已有批注的 PDF，因为选区锚点可能变化。此版本策略是根据导入器按文件名去重、PDF++ 按选区定位的机制制定的设计规则。

将来引入 Zotero Integration 时，先使用 `persist` 等机制保护个人笔记，避免重复导入覆写自己的阅读理解。[官方模板保护说明](https://github.com/community-archive/obsidian-zotero-integration/blob/main/docs/Templating.md#how-do-i-prevent-sections-of-my-templates-from-being-overwritten)

## 4. 项目区：采用 Linear 的层级和工作习惯

每个项目一个目录，采用 **Project → Milestone → Task**：

- 项目写问题与成功标准。
- 里程碑写阶段交付物与验收条件。
- 任务写可执行步骤、安排、依赖和结果证据。

任务属性包括 `project`、`milestone`、`status`、`priority`、`scheduled`、`due`、`depends_on`、`blocked`、`evidence`。`scheduled` 是安排日期，`due` 是截止日期。项目 ID 使用全库唯一编号，任务 ID 以项目编号开头。

任务流转为 `backlog → ready → doing → review → done`，另有 `cancelled`。完成必须有验收和证据，失败实验也可以是合格产出。依赖阻塞通过 `blocked` 和说明单独保存，不覆盖任务当前阶段。

### 当前版本的展示方式

你的实际 Obsidian 版本是 **1.12.7**，Bases 已启用。模板包使用表格和按属性分组，提供：项目组合、工作队列、未来七天与积压、风险与阻塞、待验收，以及嵌入项目主页的阶段/任务视图。[Bases 语法](https://obsidian.md/help/bases/syntax)

最新原生 Kanban 需要 Obsidian 1.14+，当前包不依赖它；以后升级后可以在同一数据上添加看板，跨列拖动直接更新状态属性。[官方版本要求与操作](https://obsidian.md/help/bases/views/kanban)

项目工作视图使用嵌入页面的 `project_id` 筛选，不为每个项目复制一套查询。单独打开 `项目工作.base` 时没有所属项目上下文，请从项目主页看它。

### 示例：具身 RL 代码掌握

| 里程碑 | 相对周次 | 可验收产出 |
| --- | --- | --- |
| M01 PPO 代码素养 | W1–4 | 可训练 Mini PPO、公式到代码映射 |
| M02 模块化机器人 RL | W5–8 | Runner→Storage→PPO 图、G1 pipeline 审计 |
| M03 G1 环境修改 | W9–12 | 观测/动作字典、Reward Ablation、修改报告 |
| M04 陌生仓库审计 | W13–16 | BFM-Zero 非平凡修改、90 分钟陌生仓库审计 |

四个节点取自你现有学习路线的阶段目标；没有虚构已完成进度。项目开始日和截止日留空。三条示例任务展示排期与依赖结构，实施时继续拆解过大的工作包。

第一版 `depends_on` 和 `blocked` 是人工维护字段，不能自动推断依赖完成，也不会自动锁住任务。正文小复选框只表示任务内部步骤，不另设一套主任务状态。

进度第一版采用“当前阶段 + 已完成/总任务 + 验收证据”，每周复盘更新。包内没有未经验证的自动百分比或跨文件依赖计算。若选装 Tasks，它主要处理正文复选框，不会自动同步任务笔记的 YAML 状态或 `depends_on`。[Tasks 查询说明](https://publish.obsidian.md/tasks/Queries/Filters)

## 5. 现有内容的迁移顺序

1. 先在独立临时 vault 中打开模板包，查看三分区和示例。
2. 正式归类时，在 Obsidian 内移动原三篇知识笔记到映射目标，使用其自动更新内部链接的设置；不同时保留同名副本作为正式笔记。
3. 导入其他新增模板和首页。原 `_文稿附件/` 路径继续保留，不移动图片。
4. 配置 Paper Importer 的三个路径，实测一次导入、一次选区旁注与双向定位。
5. 将 `打工之路.md` 中混合的论文逐篇拆成 BFM-Zero、SONIC、COINS、Effect-oriented Affordance、iGibson 2.0、iGibson 主笔记。先核准论文 ID，再补原文，不根据简称猜测链接。
6. SONIC 的运行命令、环境和故障处理归项目记录；组会记录放对应项目。原混合笔记在核对后保留为历史入口，暂不删除。

模板包中三篇知识笔记是设计预览副本，正文只调整内部知识链接、去除文稿空间的实例 ID 属性，未改写公式、代码或学习内容。`迁移映射.json` 记录来源、目标和来源内容校验值。

`sources/` 中的同步参考文件完全未修改。正式库也没有移动、重命名、写入设置或安装新插件。

## 6. 启用后的实际验收

设计包的静态检查不替代运行验收。启用时检查：

- 输入 arXiv ID 能产生 PDF 与主笔记，存入指定位置。
- 元数据和本地 PDF 链接可用；重复导入同一论文不会覆盖手写内容。
- PDF 选区复制到主笔记后显示高亮，能从旁注回原文、从反链访问旁注。
- 知识笔记图片、公式与代码保持原有内容。
- 示例项目显示四个里程碑和三个任务；在表格改状态能保存回属性。
- 设置一条测试任务的安排日期、截止日期和阻塞标记，相关视图显示正确。

现阶段没有在 Obsidian UI 中执行这些操作，因此不能宣称导入、批注及数据库展示已实测通过。
