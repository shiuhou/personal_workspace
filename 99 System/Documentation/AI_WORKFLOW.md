# 與 AI 一起使用工作區

使用者希望 AI 盡量協助日常記筆記、整理材料、更新專案與倉庫內容，而不是要求自己逐字輸入。2026-10-10 已明確暫緩排程；這份文件是日常協作約定，不是定時任務。

## 預設協作方式

使用者說「記一下」「幫我整理」「更新這個專案」或貼上相關材料時，應在授權範圍內直接完成對應檔案操作，而不只交一段讓使用者自行複製的答案。

- 先找既有筆記、論文主筆記或專案，優先補充，避免同一材料重複建檔。
- 從使用者的描述整理成可讀筆記，補上明確的來源、專案與概念連結；不要增加不必要的必填欄位。
- 歸屬不確定時先放 Inbox，只有會影響內容正確性或造成重大改動的缺失才詢問。
- 可以把專案目前重點整理為下一步待辦；AI 推導的建議標示「AI 建議」，不冒充使用者已確認的承諾或成果。
- 保留手寫理解、實驗證據與原始附件，區分來源原文、使用者觀點和 AI 推論。
- 使用者要求更新倉庫時，先完成適當檔案修改與檢查，再簡短回報改了哪些內容；普通記筆記不默認發布、推送或傳送到其他服務。

## 資料位置

- 待辦：`40 Notes/Tasks.md`（如 Notes 根目錄改變，以插件設定為準）。第一次在首頁新增後建立。
- 專案：以 `type: project` 辨識，預設在 `20 Research/`；進度為選填數字 `progress`，範圍 0 至 100。
- 首頁會從檔案重新讀取，無須維護第二份資料表。

## 更新待辦與進度的規則

1. 先讀取最新清單、相關專案及使用者當天提供的進展；保留手寫正文、未知屬性及 Wikilinks。
2. 只按使用者確認的成果勾選完成；未完成項目保留，不每天複製一份，也不默認刪除已完成項目。
3. 新任務以普通 `- [ ] 任務文字` 加入；完成以 `- [x] 任務文字` 表示。日期或時段可直接寫在文字中，目前沒有日曆解析或提醒。
4. 只有使用者提供百分比或同意具體計算依據時，才更新 progress。不以編輯次數、檔案數或 AI 猜測代替進度；資料不足就保留原值，沒有原值則留空。
5. 修改前重讀目標檔案，避免覆蓋同時發生的手寫修改；只改需要更新的行及屬性。
6. 回報新增／完成的待辦及進度變更；不自動發布、推送、發訊息或建立其他任務。

## 可直接對 AI 說

> 幫我記下和整理今天的內容，連到相關課程或研究專案。根據我提供的進展，更新此 Vault 的 Tasks.md 及相關專案 progress。保留未完成事項、已完成記錄、原文和未知屬性；不要猜測完成或百分比。先讀取最新檔案再修改，最後列出變更與仍需我確認的資訊。

若未來要求定時執行，需先確定執行時間、可讀取的進展來源和寫回的 Vault。排程本身不能從缺少的資訊得知任務是否完成。

## 2026-10-11：安排、記錄與續接格式

本輪最新範圍已加入基本日曆與工作記錄，取代以上「目前沒有日曆解析」的歷史描述。自動排程仍未設定。以下路徑以預設 Notes 根目錄示意；修改前查插件設定和實際檔案，不能另建第二份待辦。

### 任務

普通 Markdown checkbox 是唯一正式狀態。選填 `[priority:: high|normal|low]`、`[due:: YYYY-MM-DD]`、`^task-識別碼`。未知欄位與其他正文保留；已有 ID 不重建。需要引用任務時才補穩定 block ID，關聯用 `[[40 Notes/Tasks#^task-識別碼]]`。

AI 尚未獲使用者採納的候選，在同一清單用 `[state:: suggested]` 標記。不得勾成已完成、直接排入今天或移除這個標記冒充確認。已確認的待辦與未完成項目不每天複製。

### 計劃安排

`40 Notes/Schedule/*.md`：`type: note`、`kind: schedule`，可讀 YAML 中保存 `id`、`title`、`start`、`end`、`timezone`。start/end 使用帶 Z／明確 offset 的 ISO instant；timezone 是 IANA 名稱。選填 task、projects 清單及 course 都是 Wikilinks，正文是簡記。

安排只代表計劃。移動或結束時間塊不能完成任務、產生「實際工作」或推算掌握度。重疊需回報，不自動挪動其他安排。刪除以 status: archived 封存；保留原文，可移除 archived 恢復。沒有重複事件系列格式，不自行添加 recurrence 並宣稱界面支持。

### 工作記錄

`40 Notes/Records/*.md`：`type: note`、`kind: work-log`、`status: draft`、title、date、created、id；選填 projects、course、task、source。正文使用：

```md
## 目標

## 過程

## 結果

## 未來計劃
```

四段式是整理結果，不是必填表格。只有一句簡記時放過程，其餘留空；不能補造目標、結果或理解結論。插件保存原始輸入於 `<details>`，用 `<!-- lr:raw-start -->`／`<!-- lr:raw-end -->` 標明；AI 不覆寫此區。若來源是已有筆記，source 寫明確連結；外部來源未知則留空。引用需保留頁碼、段落或原文定位，不將 AI 推論標成原文。

使用者修正與原始輸入分開。再整理先重讀最新正文，只增量改確定需要的段落；如需替換既有草稿，提供目前／新草稿對照，不能靜默覆寫。原文重試用同一操作 ID；同 ID 已存在但內容不同，應回報路徑並核對，不新建重複筆記。

### 日記與續接

`40 Notes/Journal/YYYY-MM-DD.md`：`type: note`、`kind: journal`、date。它是可編輯的已有記錄組合，帶每份來源連結。沒有記錄時寫「尚未記錄」；局部資料、失敗結果如實顯示。日记不是第二份任務資料，也不自動新增任務。

整理已有日記時載入目前修正，不直接用重新生成版本蓋掉。插件的重新組合需要預覽並明確套用；AI 遵循同樣約定。

續接上下文取自相關任務／專案的已有工作記錄：目前目標、可靠結果、未解問題／下一步和來源。缺項留「尚未記錄」，不要建立需要重複維護的 Context 表，不憑同專案就把所有來源當成直接相關。

### 操作回報

說明實際新增／修改的檔案、保留的來源、需要使用者確認的候選；本地保存不代表另一台已同步。複製整理指令不代表 AI 已執行，預覽不代表已保存。普通筆記授權不包含 git push、私人內容上傳或改變可見性。
