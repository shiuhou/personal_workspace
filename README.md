# personal_workspace

一個建於 Obsidian 的 **Personal Learning & Research Workspace**，也是我希望能與 AI 一起使用的個人學習與研究 OS。

這裡的 OS 指承載日常學習、研究、材料與思考的工作環境。Obsidian 是平台，普通 Markdown、YAML 與本地附件是資料來源，自訂插件提供首頁、導覽與整理介面。

## 為什麼做這個 OS

我想把大學課程、講義、作業、筆記、論文、研究專案、實驗與想法放在一個容易使用、能長期累積的地方。打開它時，應該能看懂目前有哪些學習與研究方向、最近在做甚麼、有哪些待辦，以及下一步可以從哪裡繼續。

漂亮的介面有實際用途：讓我容易找到材料、理解它們之間的關係，並願意回來使用。首頁和分類頁應像一個完整的個人應用，提供清楚的入口；空資料時也應有合適的說明與操作。

更重要的是，**我不可能把這麼多內容逐字手寫、逐項分類，所以 AI 應該參與日常使用。** 我可以講目標、貼材料、描述進展，讓 AI 幫忙整理成筆記、連到既有專案、補充來源和更新待辦。我的精力主要放在理解、判斷和實際研究上。

這套系統最終要做到的是：資料容易放進來，之後找得回來，知識能重用，研究過程與證據能接得起來。

## 我希望怎樣與 AI 一起使用

AI 是協助操作這個工作區的夥伴。當我授權它記錄或更新內容時，應找到合適的檔案，實際完成修改，再簡短回報結果。

| 我提供的內容或要求 | AI 應協助完成的工作 |
| --- | --- |
| 「幫我記一下這個想法」 | 建立或補充想法／筆記；歸屬不確定時先放 Inbox |
| 貼上講義、文章或論文材料 | 整理有來源的閱讀筆記，連到相關課程、專案或概念 |
| 「這個概念我想再弄清楚」 | 協助解釋與整理理解；需要重用時再拆成概念筆記 |
| 描述今天做了哪些實驗、遇到甚麼問題 | 補充實驗紀錄、結果、證據、疑問與下一步 |
| 「更新這個專案」 | 先讀既有內容，再更新當前重點、待辦與有依據的進度 |
| 「整理一下倉庫內容」 | 優先整合已有檔案、補連結並避免重複，保留原文與未知屬性 |

我應該能用自然語言交代事情，不需要先填好一大堆 metadata，也不需要每次把 AI 的回答自行複製到筆記。AI 需要保留我的手寫理解，區分原始資料、我的觀點與它的推論；資料不足時保留疑問，不編造閱讀結論、實驗成果或完成狀態。

**目前的協作方式是由能存取 Vault 的 AI 工具讀寫本地檔案。** Obsidian 插件會反映這些檔案變更；插件本身尚未內建 AI 聊天或模型呼叫。日常筆記更新不代表自動推送 GitHub 或傳送到其他服務。具體約定見 [AI_WORKFLOW](99%20System/Documentation/AI_WORKFLOW.md)。

## 資料怎樣組織

核心物件保持七種：Course、Research Project、Paper、Note、Experiment、Idea、Resource。概念筆記是 Note 的一種用途，不另建一套重複系統。

研究部分採用「知識、來源、實踐」的分工：

- **知識與理解**：保存自己的理解與可重用概念。長筆記可以保留，有實際重用需求才拆分。
- **論文與來源**：每篇論文盡量維持一份主筆記與對應 PDF，保留引用定位和個人閱讀理解。
- **實踐與證據**：專案組織問題、決策和成果；實驗保存設定、過程、結果與解讀，失敗同樣留下來。

三者透過可讀連結相互連接。同一篇論文可以支持多個專案，無須複製多份。課程也能連到相關概念與研究材料，讓學習成果繼續被使用。

## 必須保留的原則

- **本地檔案是唯一資料來源。** 核心知識保存在普通 Markdown／YAML、PDF、圖片等檔案中；停用自訂 UI 後仍可閱讀和移轉。
- **資料與介面分離。** 插件索引可重建，不在快取或不透明資料庫裡保存唯一資訊。
- **沿用 Obsidian 的能力。** 編輯器、PDF、檔案、搜尋和連結使用原生功能；自訂介面集中改善瀏覽、關聯與建立流程。
- **低摩擦、少依賴。** 好的預設值比大量必填欄位重要；維持少量物件、清楚模板和一個主要插件。
- **資訊必須真實。** 數量來自檔案，進度有明確依據；不放假課程、假論文或推算的生產力分數。
- **AI 按需求參與。** 協助理解、記錄和整理，不進行桌面監控、時間追蹤或背景活動分析。

## 現階段與接下來的計劃

### 1. 建立可用的工作區基礎

目前已有 Home、Tasks、Records、Courses、Research、Papers、Experiments、Ideas、Inbox，以及 Recent、Pinned、Library。支援模板建立、關聯彙整、原生筆記編輯與 PDF 並排閱讀。

首頁也加入了後續確認的兩項需求：

- **待辦清單**：可以手寫新增，也可以讓 AI 更新，保存為 `40 Notes/Tasks.md` 的普通 Markdown 核取方塊。
- **專案進度條**：使用專案筆記中的 `progress` 數字，範圍為 0–100；沒有資料就顯示「尚未設定」。AI 可依我提供的百分比或已同意的計算依據更新，不從活動量猜測。

2026-10-11 接續「功能與 UI 完善」：Home 改為本週／今日安排與優先待辦、續接入口；加入可保存的安排、任務詳情、工作記錄、按需日記與原文查找。資料仍是同一份 Tasks.md 及 Note 變體；沒有里程碑依賴、外部整合或自動排程。本輪 56 項測試與建置通過，Mac Obsidian 1.14.4 已驗證安排建立／拖移／調整／恢復、待辦、記錄與日記保存、本地匯出、明暗首頁及窄分割面板。Windows 與精確尺寸矩陣未實測，详细範圍見 VALIDATION。使用與格式見工作區文件。

### 2. 把它真正用進日常學習與研究

下一步以真實課程、論文、專案和實驗來使用這個工作區，讓 AI 協助捕捉與整理，逐步建立可延續的研究脈絡。根據實際使用中的阻力，改善建立、查找、閱讀與更新流程。

先確認這些基本問題：材料是否容易放進來？AI 能否找到並更新正確的筆記？過一段時間後是否仍能理解當時的思路？相關知識、來源與證據是否找得到？

### 3. 完成驗收並維持可靠性

截至 2026-10-10 的開發紀錄，37 項自動測試通過，並已在 Obsidian 1.14.4 驗證主要建立與關聯流程、PDF 並排、重新命名、待辦、進度與置頂。基礎介面有明暗模式觀察；新增元件與所有情境仍需依驗收紀錄逐項確認。

外部檔案匯入的完整 GUI 流程、Force Reload 偶發空白視窗，以及手機、其他主題和大型 Vault 等仍有未驗證或待處理項目。自動測試通過不等於全部實機驗收完成，詳細狀態以 [VALIDATION](99%20System/Documentation/VALIDATION.md) 和 [HANDOFF](99%20System/Documentation/HANDOFF.md) 為準。

### 4. 有實際需要才擴充

更深入的 PDF 批注、大量論文匯入，以及針對論文、課程或專案的按需 AI 操作，都應由真實使用需求決定。維持檔案格式可攜，避免過早綁定特定 AI 供應商或重做現有工具。

**自動排程已暫緩，沒有啟用。** 目前的重點是讓 AI 幫忙日常記筆記和更新內容；日後若重新需要定時整理，再確認執行時間、資料來源和更新規則。本地使用也不要求先建立雲端環境。

## 開發

雲端環境的安裝命令可使用 `bash .codex/setup.sh`，會進入隱藏的插件目錄並以固定 pnpm 版本安裝鎖定依賴。根目錄的 `AGENTS.md` 提供接續開發與驗證指引。這些檔案只準備建置環境，不代表 Codex Cloud 環境已建立或發布。

插件完整原始碼與目前建置產物位於 `.obsidian/plugins/learning-research-workspace/`。使用 Node.js 22+ 與 pnpm：

```sh
cd .obsidian/plugins/learning-research-workspace
pnpm install --frozen-lockfile
pnpm test
pnpm run build
```

此倉庫根目錄也是 Obsidian Vault。以 Obsidian 開啟，啟用本地 Learning & Research Workspace 插件即可進行實機除錯。重新建置後須重新載入插件。無後端、雲端資料庫、AI API key 或額外 UI runtime。

`node_modules`、個人視窗布局、快取、測試 Demo 與環境密鑰檔不納入版本管理。正式內容由實際使用逐步累積；測試資料只放在 `99 System/Demo/`，驗收後清除。
